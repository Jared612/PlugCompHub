## 1.0 范围与术语

- **宿主（Host）**：加载 `pcx` 动态库并调用能力的进程。常规用法只包含 [`pcxcore/include/pcx.h`](../pcxcore/include/pcx.h) 中的 `pcx::api`，运行时按符号名解析 `Initialize` / `Terminate` 等（见 [`pcxcore/include/pcxexport.h`](../pcxcore/include/pcxexport.h)）。
- **组件（Component）**：由 `ComponentInfo`（creator / deletor / `getMessageHandler`）描述的工厂单元；通过 `PCX_REGISTER_COMPONENT` 等宏静态注册到 [`pcxcore/include/pcxcomponent.h`](../pcxcore/include/pcxcomponent.h)。
- **插件（Plugin）**：独立动态库，导出标准入口 `pluginfo` / `pluginit`（见 [`pcxcore/include/pcxplugin.h`](../pcxcore/include/pcxplugin.h)），由 `PluginManager` 加载并向 `ComponentManager` 注册其组件表。
- **对象（Object）**：组件的运行时实例，由 `ObjectManager` 管理；可具名注册供 `FindObject` 查找，也可匿名创建由调用方负责删除（见 `pcx::api::CreateObject` / `DeleteObject`）。

### 生命周期与所有权约定（重要）

- `ComponentInfo` 由 `PCX_REGISTER_COMPONENT` 宏定义为模板特化的静态常量（`ComponentTmpl<T>::componentInfo`），位于其所在动态库/可执行文件的静态存储区。`ComponentManager::registerComponent` 等只把该指针登记为观察指针，**不拥有也不 `delete` 它**。
- `Component*` 封装对象由 `ComponentManager` 持有：注册成功后归管理器释放；重复注册时本函数接管并销毁传入的 `Component*`，避免调用方与管理器重复释放。
- `ObjectInfo*` 由 `ObjectManager` 持有；通过 `ComponentInfo::deletor` 释放真正的对象实例。
- 匿名对象与具名对象都会进入地址映射表 `_regObjAddrMap`，因此 `DeleteObject(void*)` 一律 O(1)；`getObjectName` 对匿名对象返回空串 `""`、未知指针返回 `nullptr`（见 `IObjectManager::getObjectName` 注释）。
- `CreateObject` / `CreateNamedObject` 的 `initMsg` 仅作为消息原样通过 `IMessageCenter::invokeHandler` 投递给目标对象；**消息码由调用方在 `allocMessage` 时设置**（1.0 不再在 ObjectManager 内强行改写 `_code`，也不对 `IMessage*` 做 `Message*` 强转）。
- `PluginManager::unloadPlugin` 先注销其组件（让 `findComp` 立刻失败、阻断新 `createObject`），再检测本插件是否仍有活对象：若有，**回滚注销并返回 `PCX_NOTALLOW`**；否则从插件表移除、销毁 `Plugin`（由其析构 `FreeLibrary` / `dlclose`）。上层应避免与业务对象创建并发 unload，彻底串行化需要业务侧协作。
- 核心默认对象 `PCX_DEFAULT_OBJECTMANAGER` / `PLUGINMANAGER` / `COMPONENTMANAGER` / `MESSAGECENTER` / `LOGGERMANAGER` / `ENVIROMENT` 被显式加入 `ObjectManager` 的删除黑名单：通过 `deleteObjectByName` / `deleteObject(void*)` 误删时返回 `PCX_NOTALLOW`，只能经由 `pcxcoreStop` 按序销毁。
- `Initialize` 具备幂等：若 `_objManager` 已非空会直接返回 `PCX_SUCCESS`、复用现有管理器指针，避免重复启动产生孤儿对象。

### 消息中心所有权与异步语义（重要）

- **消息所有权**：`sendMessage` / `postMessage` / 所有 `multicastLocal*` / `broadcastLocal*` 不论成功或失败，一律由消息中心负责 `freeMessage(request/message)`；调用方在成功传入之后**不得**再使用或释放该消息。错误路径（目标缺失、`_objManager` 未就绪、`BreakOnError` 中断等）同样遵守此约定。
- **响应消息所有权**：同步 `sendMessage` 返回的 `response` 非空时由调用方 `freeMessage`；若 handler 误把 `req` 原样当作 response 返回，框架会在 `invokeHandler` 内识别并丢弃引用，避免双重释放。
- **异步队列的目标解析**：本地异步路径（`postMessage` / `multicast*Async` / `broadcastMessageAsync`）在入队时仅记录目标**对象名**，工作线程在派发前重新按名解析 `ObjectInfo`，目标已被删除时跳过该条投递——以此规避"入队时取裸 `ObjectInfo*`、worker 解引用时对象已销毁"的 UAF。匿名对象（无名字）不进入异步广播集合。
- **退出时消息回收**：`~MessageCenter` 在 `join` 工作线程后会清空 `_messages` 中尚未派发的消息，避免退出时消息缓冲泄漏。
- **目标数量窄化保护**：`IMessage::getTargetsCount` 返回 `uint16_t`，实现对 `_targets.size() > UINT16_MAX` 的情况做截断返回 `UINT16_MAX`，避免静默溢出为小值；如需真正支持 >6.5w 接收者，应按 ABI 兼容方式升级接口到 `uint32_t`。

### 日志、动态库句柄与线程池的收尾性修复（1.0 末期）

- **全局 `_pcxLogger` 原子化**：`WriteLog` 读取的全局指针改为 `std::atomic<LoggerLevelCtrl*>`，配合 `LoggerManager::~LoggerManager()` 统一置空，**避免**宿主未走 `SystemShutdown` 路径直接 `Terminate` 时，其他线程在 `LoggerManager` 析构后继续写日志导致 UAF。
- **`__linkto` 对应 `__unlinkfrom`**：`pcx::api::Terminate` 调用后，通过 `__unlinkfrom` 释放之前 `LoadLibrary`/`dlopen` 缓存的句柄，解决进程期句柄泄漏与 DLL 无法热替换的问题；多次调用安全。
- **`ComponentManager::reregisterFromDeleteList`**：`PluginManager::unloadPlugin` 回滚路径优先从延迟删除队列里还原原 `Component*`，避免每次"unregister→register"循环都新建包装并把旧包装悬留在 `_deleteComponents`。
- **`PCX_PLUGIN_INFO_BEGIN` 跨平台对齐**：Windows 分支也通过 `VARGS` 实现 2/3 参数派发；`VARGS` / `CONCAT` / `PCX_EXPAND` 提升为公共宏，写法与 Linux/macOS 一致。
- **`ObjectInfo::counter` 死字段清理**：原字段恒为 1 从未递增，`getRefCount` 语义退化为"存在性判断"。为避免歧义移除了该字段，`getRefCount` 改为命中返回 1、未命中返回 0，并显式说明 1.0 暂不实现自动引用计数。
- **线程池 worker 数据竞争**：`PcxThreadPool::workerLoop` 判空 `_tasks.empty()` 的决策重新回到持锁路径，避免与 `exec()` 的入队并发读写 `std::queue` 成员。

## 扩展模块（可选构建目标）

根 [`CMakeLists.txt`](../CMakeLists.txt) 通过 `if(EXISTS ...)` 条件加入子目录；存在对应目录与 `CMakeLists.txt` 时才会构建。

| 模块 | 职责概要 | 对外头文件 |
|---|---|---|
| pcxapplication | 按 TOML 配置启动/停止 PCX、汇总加载失败信息 | [`ipcxapplication.h`](../pcxapplication/include/ipcxapplication.h) |
| pcxnet | Boost.Asio / Beast 上的 HTTP 与 WebSocket 服务端与客户端 | `pcxnet/include/ipcx*.h` |
| pcxsqlite | SQLite 访问与简单 KV ORM | [`ipcxsqlite.h`](../pcxsqlite/include/ipcxsqlite.h)、[`ipcxsqliteorm.h`](../pcxsqlite/include/ipcxsqliteorm.h) |
| pcxthreadpool | 基于 PCX 的线程池组件 | [`ipcxthreadpool.h`](../pcxthreadpool/include/ipcxthreadpool.h) |

上述扩展库均 **链接/依赖核心 `pcx` 动态库**；`pcxnet` 额外依赖源码树内 Boost 头路径（见 `pcxnet/CMakeLists.txt`），`pcxsqlite` 将 `sqlite3.c` 编入同一目标（见 `pcxsqlite/CMakeLists.txt`）。

## 构建与安装

- **根工程**：[`CMakeLists.txt`](../CMakeLists.txt) 设置 C++14、MSVC 警告与 UTF-8、产物输出到 `${CMAKE_BINARY_DIR}/bin`（Windows 下库亦输出到 `bin`）。
- **核心库**：`pcxcore` 目标名为 `pcx`（见 `pcxcore/CMakeLists.txt`），`install` 仅安装对外公共头（不安装 `internal.h`）。
- **可选**：`threadpool` 与 `pcxthreadpool` 命名并存时二者均可被加入；`demo_pcxlib`、`example` 在存在目录时加入。
